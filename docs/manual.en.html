MGA Wwise IMImporter Manual

Take Interactive Music from “hand-built Authoring” to “listen, decide, and deliver.”

1. What makes this app stand out

Carry the music structure you designed in the DAW straight into Wwise Interactive Music.

Building Music Playlist Containers, Music Switch Containers, Music Segments, Music Tracks, State Groups, transitions, cues, and fades one by one in Authoring takes time. Preview on the waveform, decide transitions and layers by ear, then push a consistent Wwise structure with a single EXPORT. Far faster than hand-building the same graph.

You do not need Nuendo / Cubase. A WAV with markers from Logic or another DAW that can place markers already saves a lot of work. This app can also add markers and move loop-marker pairs itself—so a dedicated waveform editor is often unnecessary, which is another major benefit.

Those DAWs make it especially powerful. Export a marker-track XML and you get the most out of tempo, bar, and time-signature data. Markers and cycles can be placed on the waveform as if painting them on, so Entry / Exit / loop design stays visual.

The workflow assumes the Interactive Music data in Wwise is the master. Keep one-shot and loop material on a single master waveform instead of pre-separating files; build structure nondestructively, then EXPORT cut ranges plus Wwise properties (MusicClip Fade / MusicFade / Make-Up Gain / Cue, and so on). Gains and fades are not baked into the source WAV.

  • Music Playlist transition preview (Exit Source At / Fade In / Fade Out / Play -E)
  • Vertical layers via grouping (Alt layering, Group Fade, Change Occurs At)
  • Streaming (Prefetch Length / Look-ahead Time) and Keep Layer Balance (Make-Up Gain)
  • Automatic Music hierarchy creation over WAAPI
  • Drop multiple waves at once, or use marker-track XML, to implement any number of pieces together

2. Loading patterns

The drop combination selects the mode. Check the log banner at the top.

2-1. Wave-only (no XML, one WAV)

Steps

  1. Drop a single .wav that has no matching .xml
  2. Confirm the log shows === Wave-only mode ===
  3. Embedded markers are loaded if present; otherwise the whole file is one part
  4. Edit markers in the app if needed (nothing is written back to the WAV)

Notes

  • No bar / tempo / signature overlay (Next Bar / Next Beat in Exit Source At are unavailable)
  • Marker Comment / Marker Grid in More Options are disabled (Wave-only uses its own marker editing)
  • Besides embedded markers, you can add, move, and set-move markers in the app (not written back to the WAV)—often without a separate waveform editor
  • Markers drive preview/region splitting and are not exported as Wwise Custom Cues
  • If the WAV has a sustain loop (smpl), its Start becomes -L and End becomes -E. These take priority over normal embedded markers; markers at the same timing as loop Start/End are discarded (logged)
  • Export names look like basename_1.wav (double-click the waveform name to edit the base name)

2-2. Multi-wave (no XML, two or more WAVs)

Steps

  1. Drop two or more .wav files together (none may have a matching .xml)
  2. Confirm the log shows === Multi-wave mode (no XML) ===
  3. Files are concatenated on a virtual timeline: one file = one Music Playlist (implement any number of pieces together)
  4. Optionally Shift-group them into vertical layers

Notes

  • Sample rate / channel count / bit depth / format must match (mismatch aborts load)
  • Per-file embedded markers / sustain loops (smpl) follow the same rules as Wave-only (sustain Start/End → -L/-E preferred; same-timing markers discarded)
  • Wwise parent name is fixed to Multi_Wave (not editable). Playlist names keep the dropped file names
  • Export keeps original file names where possible and may reuse source WAVs
  • If any file has a matching XML, this mode is not used—pair processing applies instead

2-3. WAV + matching XML (exported marker track)

Steps

  1. In Nuendo / Cubase, export the marker track as XML and place it next to a .wav with the same base name (e.g. Song.wav + Song.xml)
  2. Drop either or both
  3. Confirm the log shows === Nuendo XML mode ===
  4. Bars, tempo, signature, markers, and cycles overlay the waveform

Notes

  • Makes the most of tempo, bar, and time-signature data. Markers/cycles overlay the waveform like painted regions for clearer structure work
  • Multiple parts / pieces on one master can be implemented into Wwise together
  • XML single markers are also used as Wwise Custom Cues
  • Shift+drag on the Marker lane adds session markers; Ctrl+drag removes only those additions (XML markers stay)
  • Marker Comment / Marker Grid are enabled
  • Dropping .xml alone errors—a .wav is required

Loading caveats

  • If multiple pairs are dropped, they are processed in order, but only the last successful preview stays on screen
  • A manual drop clears the log and is treated as a fresh load (not Keep Last Session restore)
  • RELOAD / Keep Last Session restore groups, fades, and related session data when possible

3. Wwise setup and EXPORT

  1. Start Wwise Authoring and enable WAAPI (HTTP)
  2. Select the destination object in Project Explorer
  3. Set this app’s export path under the connected project’s Originals
  4. Load audio using one of the patterns above
  5. Preview transitions, fades, and grouping
  6. Run EXPORT (or Ctrl+Shift+E)

EXPORT requires: at least one valid part, WAAPI connected, destination selected, and an existing Originals path. Reasons appear under === Export Preflight ===.

6. Waveform preview

Measure / Tempo / Signature / Marker lanes, waveform, then Music Segment Name / Music Playlist Name (bar lanes are inactive without XML).

  • Click/drag to seek
  • Double-click the waveform name to edit the base name (Multi_Wave parent name is not editable in multi-wave mode)
  • White-triangle edge fades are nondestructive and become MusicClip Fade on EXPORT

7. TRANSPORT

Position → TRANS (play / G) → NAV → TIME → AMP → SIZE.

  • Space play/pause; -L regions loop
  • With Play -E on, a following -E one-shots at loop wrap (Play post-exit preview)
  • G bar jump when bar data exists
  • C / note + tempo on the position display — toggle metronome (default off; XML mode with tempo / time signature only; while playing, mixed sample-accurately into the waveform playback stream; beat 1 High, other beats Low; note and tempo turn cyan when on; mouse wheel adjusts volume from max to 10% in 10% steps, default 30%, with a ~1s Tips readout; volume is saved in app settings; on/off starts off)
  • L jump to 1 bar before loop end (or 3 seconds before without bar data)

10. What EXPORT creates in Wwise

Designed so the Interactive Music implementation in Wwise is the master. Keep one-shot and loop material on one master waveform instead of pre-separating files; build structure nondestructively. Split WAVs are cut-only; fades, layer balance, and cues become Wwise properties (nothing is baked into the source).

  • One part or one group → one Music Playlist Container
  • Two or more playlists → Music Switch Container + matching State Group
  • Group (2+ parts) → multiple Music Tracks in one Music Segment + group State Group (A/B/C…)
  • Any → Any (Exit Source At = Immediate) plus per-playlist Any → Object rules
  • Edge fades → MusicClip Fade; Keep Layer Balance → Make-Up Gain
  • Nuendo XML single markers → Custom Cues; tempo/signature Override on Music Segments

11. Suffixes and cues

SuffixMeaning
-RRemove / exclude
-LLoop
-EAfter Exit Cue (bundled into the same Music Segment)
-APickup / before Entry Cue (bundled; may be auto-assigned)

Overlapping suffixes error. A bare region after contiguous -L regions may auto-receive -E.

In Wave-only and Multi-wave modes, a WAV sustain loop (smpl) is applied as -L (Start) and -E (End). Other embedded markers (with comments) are still read, but markers at the same timing as sustain Start/End are discarded and logged.
