MGA Wwise IMImporter Manual

Take Interactive Music from “hand-built Authoring” to “listen, decide, and deliver.”

1. What this app does

Carry the music structure you designed in the DAW straight into Wwise Interactive Music.

Building Music Playlist Containers, Music Switch Containers, Music Segments, Music Tracks, State Groups, transitions, cues, and fades one by one in Wwise takes time. Preview on the waveform, decide transitions and layers by ear, then push a consistent Wwise structure with a single EXPORT. Far faster than hand-building the same graph.

You do not need Nuendo / Cubase. A WAV with markers from Logic or another DAW that can place markers already saves a lot of work. This app can also add markers and move loop-marker pairs itself—so a dedicated waveform editor is often unnecessary, which is another major benefit.

Those DAWs make it especially powerful. Export a marker-track XML and you get the most out of tempo, bar, and time-signature data. Markers and cycles can be placed on the waveform as if painting them on, so Entry / Exit / loop design stays visual.

The workflow assumes the Interactive Music data in Wwise is the master. Keep one-shot and loop material on a single master waveform instead of pre-separating files; build structure nondestructively, then EXPORT cut ranges plus Wwise properties (MusicClip Fade / MusicFade / Make-Up Gain / Cue, and so on). Gains and fades are not baked into the source WAV.

  • Music Playlist transition preview (Exit Source At / Fade In / Fade Out / Play -E)
  • Vertical layers via grouping (Alt layering, Group Fade, Change Occurs At)
  • Streaming (Prefetch Length / Look-ahead Time) and Keep Layer Balance (Make-Up Gain)
  • Automatic Music hierarchy creation over WAAPI
  • Drop multiple waves at once, or use marker-track XML, to implement any number of pieces together

2. First time here? Workflow and terms

Using the app boils down to four steps.

  1. Prepare your material — the WAV of your piece (plus an XML or markers if you have them). → Chapter 4
  2. Drop it onto the app — the mode is chosen automatically from the file combination; there is nothing to switch. → Chapter 5
  3. Listen and adjust — check loop points, transitions between pieces, fades, and vertical layers right on the waveform.
  4. Press EXPORT — WAV cutting and the Wwise structure are created automatically. → Chapter 6

This manual uses a few Wwise terms. Knowing just these is enough to follow along.

TermIn a nutshell
Interactive MusicWwise’s system for switching and layering music to follow the game state.
Music SegmentThe smallest music unit in Wwise: one stretch of audio plus a start point (Entry Cue) and an end point (Exit Cue).
Music Playlist ContainerA container that plays Music Segments in order, e.g. “intro → loop”. Called “Playlist” in this manual. Roughly “one piece (or one looping state)”.
Music Switch ContainerA parent that switches between Playlists via States (game conditions). Created automatically when there are two or more Playlists.
Entry Cue / Exit CueThe “main body start / end” of a Music Segment. Audio outside them (pickups and tails) can overlap the next piece.
Marker / cycle markerLandmarks on the waveform. A marker is a single point; a cycle marker is a range (start and end). The app reads these to learn where the loop is, etc.
WAAPIThe Wwise Authoring API — the communication channel this app uses to remote-control a running Wwise and create objects.
Originals folderThe folder inside a Wwise project where source WAVs live. This app’s export path must be somewhere under it.

3. Quick start (do this first)

Let’s put one WAV into Wwise with no special preparation — no DAW, no waveform editor. In about ten minutes you will have experienced the whole “drop → listen → EXPORT” flow.

  1. Open your project in Wwise and enable WAAPI
    In Project → User Preferences..., check Enable Wwise Authoring API and restart Wwise (one-time setup; details in Chapter 6).
  2. Select a destination in Wwise’s Project Explorer
    Click the object where generated content should go, e.g. the Default Work Unit under Interactive Music Hierarchy.
  3. Start this app
    If the WAAPI status bar at the bottom shows the Wwise version, project name, and the selected destination, you are connected.
  4. Set the export path
    In the project bar, point the export path at a folder under your Wwise project’s Originals folder (e.g. Originals\Music; create it in Explorer if needed).
  5. Drag and drop one WAV
    The log shows === Wave-only mode === and the waveform appears. Space plays it.
  6. (To loop it) place two markers
    Click the waveform to seek to the loop start and press Insert to add a marker; do the same at the loop end. With exactly two markers, the span between them automatically becomes the loop (before the first marker = intro, after the second = tail). Drag the ▼ handles to fine-tune.
  7. Listen
    Press Space; the loop region repeats endlessly. Nudge the markers until it feels right.
  8. EXPORT (or Ctrl+Shift+E)
    The cut WAVs are saved to the export path and a full Music Playlist Container setup is generated in Wwise. Play it in Wwise to confirm.

If the EXPORT button is disabled, the reason (not connected, no destination selected, export path not under Originals, etc.) is written in the log under === Export Preflight ===. → Chapter 15

“Place markers to define ranges” is the core operation of this app. Once comfortable, move on to methods A / B in the next chapter to bring in material from your DAW — tempo sync and batch implementation of many pieces become available.

4. Preparing your material: 3 methods

There are three ways to bring a piece into the app. The method is detected automatically from the files you drop — there is nothing to switch in the app. In every method you can still edit markers inside the app after loading (nondestructive; the original WAV is never modified).

4-1. Which method to use

MethodWhat you prepareBest forWhat you get
A: Nuendo / Cubase XMLRecommended Song.wav + Song.xml with the same base name (exported marker track) You use Nuendo / Cubase and need bar / tempo management (Next Bar transitions, Custom Cues, several pieces on one master, etc.) Bar / tempo / time-signature overlay, bar-based operations (Next Bar / Next Beat, metronome, bar jump), single markers → Custom Cues, “paint” markers onto the waveform
B: WAV with markers A .wav with embedded markers (or a sustain loop) Any DAW that can export a WAV with embedded markers (including a Nuendo / Cubase mixdown). Enough for a simple intro + loop piece Loop / exclude ranges recognized automatically from embedded markers. No bar / tempo data
C: Plain WAV Just a .wav (zero preparation) Trying the app out / only have plain WAVs / batch-importing finished loops Add markers inside the app to define ranges. Drop two or more files together to implement many pieces at once (multi-wave mode)

If you are unsure:

  • First time? → Method C (follow the quick start). Zero preparation, full workflow.
  • Using Nuendo / Cubase? → Make it a habit to export your mixdowns with the iXML chunk and markers included (a small extra step, but close to essential). For a simple “intro, then loop” piece, that alone (Method B) is enough to implement it. Only when you need bar / tempo management (Next Bar / Next Beat transitions, Custom Cues, several pieces on one master, etc.) do you additionally export the marker-track XML and use Method A.
  • Using another DAW? → Method B. Just export a WAV with markers to bring in your loop design.
  • Lots of already-looped tracks? → Method C’s multi-wave mode. Drop them all at once for batch implementation.

A WAV with no markers at all still loads. You would then place loop markers inside the app, which is not much different from punching them in a waveform editor — but the cutting and Wwise-side implementation are still automated, and loops are easy to dial in. If you can, at least export with markers included (Method B).

Common WAV requirements: use uncompressed PCM .wav. The file name (without extension) becomes the Wwise object name, so names that start with a digit (e.g. 01_Battle.wav) or are Windows reserved names (CON, AUX, ...) are rejected at load. When dropping multiple WAVs together, sample rate, channel count, and bit depth must match across all files.

4-2. Method A: preparing a Nuendo / Cubase XMLRecommended

Export two files from your Nuendo / Cubase project — the marker-track XML and the WAV — and put them in the same folder with the same base name (e.g. Song.wav and Song.xml).

The XML export is an extra step that enables bar / tempo-managed interactive music. For a piece that simply has an intro and then loops, the XML is not required — a WAV with embedded markers (4-3) is all you need. Method A is optional, not mandatory.

① Place markers in the DAW

Lay out the piece’s structure on the marker track using these naming rules (matched on the name’s ending, case-insensitive).

What to placeName ends withMeaning
Cycle marker (range)-LLoop range. Loops endlessly in preview and becomes a looping Music Segment in Wwise.
Cycle marker (range)-EAfter the Exit Cue (the tail / release after the loop). Bundled into the same Music Segment as the loop, so it overlaps the next piece on transition.
If you forget an -E right after an -L, it is added automatically.
Cycle marker (range)-RRemove (exclude). This range is neither exported nor registered in Wwise. Use it as a divider between pieces when placing several on one master.
Single marker (point)(any name)Becomes a Wwise Custom Cue (the name is the cue name). Useful as sync points for the game.
  • Never let -L / -E / -R ranges overlap (overlaps are a load error).
  • The waveform is split automatically at cycle In/Out points, at bar starts where the tempo changes, and at time-signature changes. Each run of contiguous non-excluded regions between -R dividers becomes one exported file = one Music Playlist, so a single master WAV can carry several pieces and implement them all at once.
  • If the piece starts mid-bar (a pickup / anacrusis), that is detected automatically and placed before the Entry Cue as an -A region. You normally never write -A yourself.

② Export the marker track as XML

  1. In the track list, select the marker track. The marker track is the one to export — exporting the tempo or signature track instead does not contain enough information.
  2. Run File → Export → Selected Tracks and save as .xml.
  3. Use the same base name as the WAV (Song.xml next to Song.wav).

An XML exported from the marker track also carries the tempo and time-signature data. If loading reports “MTempoTrackEvent (Tempo Track) was not found”, check that it was the marker track you selected for export (tempo/signature-track-only exports are insufficient).

③ Export the WAV

  1. From the same project, export the audio via File → Export → Audio Mixdown as .wav.
  2. In the export options, enable both the iXML chunk and marker embedding (recommended, close to essential). The iXML chunk records the timeline start position (TimeReference) in the WAV so bar lines align exactly with the audio.
  3. In the marker option, always verify that the intended marker track is the embed target. If another track is still selected there, you may think markers were embedded when they were not.
  4. Save it in the same folder with the same base name as the XML.

If you cannot include iXML, place the piece at the very start of the project (bar 1) and export from the top — with no TimeReference (or 0), the waveform start is assumed to be the timeline start. If the piece sits mid-timeline, iXML is required.

④ Drop

Drop either Song.wav or Song.xml (or both) onto the app; both are loaded automatically. When the log shows === Nuendo/Cubase XML mode ===, you are set — bars, tempo, signature, markers, and cycles overlay the waveform.

4-3. Method B: preparing a WAV with markers

Any DAW or waveform editor that can embed markers into a WAV works — Logic included. A Nuendo / Cubase Audio Mixdown with marker embedding enabled also produces this kind of WAV — for a simple “intro, then loop” piece it is all you need, no XML required. Two kinds of metadata are read.

  • Sustain loop (smpl chunk) — sampler loop data. If present it takes top priority: the loop Start is treated as -L and the End as -E. Regular markers at exactly the same position as the loop Start/End are discarded (logged).
  • Regular markers (cue points) — interpreted by name (comment).

Marker-name rules. Each range runs “from this marker to the next marker (or the end of the file)”.

Marker nameMeaning
-LLoop range starts here.
-EAfter-Exit-Cue (tail) range starts here.
-RExcluded (not exported) range starts here.
-ABefore-Entry-Cue (pickup) range starts here.
Name containing LoopTreated like -L. Two of them bracket a loop range (an unpaired odd one acts as a lone -L).
Any other nameNo effect on ranges (display / editing landmark only).
  • Special case: with exactly two markers and no special names, the span between them automatically becomes the loop. A WAV where you simply dropped two plain markers at the loop points works as-is.
  • With no special markers at all, the whole file is one part (start = Entry Cue, end = Exit Cue). One-shot pieces need no markers.
  • No bar lines or tempo are shown (use Method A if you want tempo-synced features).
  • WAVs that contain only regions (cue + ltxt) are not supported yet. Use point markers or a sustain loop.
  • Embedded markers drive preview and region splitting only — they are not exported as Wwise Custom Cues (use Method A’s single markers for Custom Cues).

4-4. Method C: starting from a plain WAV (markers in the app)

No preparation needed. Drop the .wav as-is and define ranges by placing markers in the app, on the marker lane below the waveform (the original WAV is never written to).

  • Insert — add a marker at the seek position
  • Drag ▼ — move a marker (Alt+drag also moves the previous marker by the same amount — handy for sliding a loop range while keeping its length)
  • Double-click ▼ or the comment — edit the name (comment); -L / -E / -R / -A mean the same as in Method B
  • Delete — remove the selected marker; Ctrl+Z / Y — Undo / Redo

To implement many pieces at once, drop two or more WAVs together (multi-wave mode). They are laid out on a concatenated virtual timeline, one file = one Music Playlist, and registered to Wwise in one batch. Each file’s embedded markers (Method B rules) still apply.

5. How the loading mode is chosen

The drop combination selects the mode. Check the log banner at the top.

What you droppedMode (log banner)
One .wav (no matching .xml)=== Wave-only mode ===
Two or more .wav (none with a matching .xml)=== Multi-wave mode (no XML) ===
Matching .wav + .xml (dropping either one is enough)=== Nuendo/Cubase XML mode ===
.xml alone (no matching .wav found)Error (a .wav is required to show the waveform)

5-1. Wave-only (no XML, one WAV)

Steps

  1. Drop a single .wav that has no matching .xml
  2. Confirm the log shows === Wave-only mode ===
  3. Embedded markers are loaded if present; otherwise the whole file is one part
  4. Edit markers in the app if needed (nothing is written back to the WAV)

Notes

  • No bar / tempo / signature overlay (Next Bar / Next Beat in Exit Source At are unavailable)
  • Marker Comment / Marker Grid in More Options are disabled (Wave-only uses the marker editing in 4-4)
  • Besides embedded markers, you can add, move, and pair-move markers in the app (not written back to the WAV)—often without a separate waveform editor
  • Markers drive preview/region splitting and are not exported as Wwise Custom Cues
  • If the WAV has a sustain loop (smpl), its Start becomes -L and End becomes -E. These take priority over normal embedded markers; markers at the same timing as loop Start/End are discarded (logged)
  • Export names look like basename_1.wav (double-click the waveform name to edit the base name)

5-2. Multi-wave (no XML, two or more WAVs)

Steps

  1. Drop two or more .wav files together (none may have a matching .xml)
  2. Confirm the log shows === Multi-wave mode (no XML) ===
  3. Files are concatenated on a virtual timeline: one file = one Music Playlist (implement any number of pieces together)
  4. Optionally Shift-group them into vertical layers

Notes

  • Sample rate / channel count / bit depth / format must match (mismatch aborts load)
  • Per-file embedded markers / sustain loops (smpl) follow the same rules as Wave-only (sustain Start/End → -L/-E preferred; same-timing markers discarded)
  • Wwise parent name is fixed to Multi_Wave (not editable). Playlist names keep the dropped file names
  • Export keeps original file names where possible and may reuse source WAVs
  • If any file has a matching XML, this mode is not used—pair processing applies instead

5-3. WAV + matching XML (exported marker track)

Steps (how to create the XML and WAV: 4-2)

  1. In Nuendo / Cubase, export the marker track as XML and place it next to a .wav with the same base name (e.g. Song.wav + Song.xml)
  2. Drop either or both
  3. Confirm the log shows === Nuendo/Cubase XML mode ===
  4. Bars, tempo, signature, markers, and cycles overlay the waveform

Notes

  • Makes the most of tempo, bar, and time-signature data. Markers/cycles overlay the waveform like painted regions for clearer structure work
  • Multiple parts / pieces on one master can be implemented into Wwise together
  • XML single markers are also used as Wwise Custom Cues
  • Shift+drag on the Marker lane adds session markers; Ctrl+drag removes only those additions (XML markers stay)
  • Marker Comment / Marker Grid are enabled
  • Dropping .xml alone errors—a .wav is required

Loading caveats

  • If multiple pairs are dropped, they are processed in order, but only the last successful preview stays on screen
  • A manual drop clears the log and is treated as a fresh load (not Keep Last Session restore)
  • RELOAD / Keep Last Session restore groups, fades, and related session data when possible

6. Wwise setup and EXPORT

6-1. Enable WAAPI (one-time setup)

This app talks to the running Wwise Authoring over WAAPI (HTTP) to create objects.

  1. In Wwise, open Project → User Preferences...
  2. Check Enable Wwise Authoring API and press OK
  3. Restart Wwise

The app always connects to http://127.0.0.1:8090/waapi (Wwise on the same PC, HTTP port 8090). If you changed the HTTP port in User Preferences, set it back to the default 8090.

6-2. Destination and export path

  • Destination — in Wwise’s Project Explorer, click the object that should receive the generated content (a Work Unit or Virtual Folder under Interactive Music Hierarchy, etc.). The app uses “whatever is currently selected in Wwise” as the destination. If reselecting every time is tedious, pin it with Keep Target on the action bar.
  • Export path — set in the project bar; where the cut WAVs are saved. It must be under the connected Wwise project’s Originals folder (e.g. <project>\Originals\Music\IMImporter) so Wwise can reference the source WAVs.

6-3. EXPORT procedure

  1. Start Wwise Authoring with WAAPI enabled (6-1)
  2. Select the destination object in Project Explorer
  3. Set this app’s export path under the connected project’s Originals
  4. Load audio using one of the patterns in Chapter 5
  5. Preview transitions, fades, and grouping
  6. Run EXPORT (or Ctrl+Shift+E)

EXPORT becomes available when all four conditions hold: ① at least one valid part ② WAAPI connected ③ destination selected ④ export path exists and is under Originals. Reasons appear under === Export Preflight === in the log.

13. What EXPORT creates in Wwise

Designed so the Interactive Music implementation in Wwise is the master. Keep one-shot and loop material on one master waveform instead of pre-separating files; build structure nondestructively. Split WAVs are cut-only; fades, layer balance, and cues become Wwise properties (nothing is baked into the source).

  • One part or one group → one Music Playlist Container
  • Two or more playlists → Music Switch Container + matching State Group
  • Group (2+ parts) → multiple Music Tracks in one Music Segment + group State Group (A/B/C…)
  • Any → Any (Exit Source At = Immediate) plus per-playlist Any → Object rules
  • Default rule (Any to Any) inside each playlist container → Play post-exit follows Play -E
  • Edge fades → MusicClip Fade; Keep Layer Balance → Make-Up Gain
  • Nuendo/Cubase XML single markers → Custom Cues; tempo/signature Override on Music Segments

14. Suffixes and cues

SuffixMeaning
-RRemove / exclude
-LLoop
-EAfter Exit Cue (bundled into the same Music Segment)
-APickup / before Entry Cue (bundled; may be auto-assigned)

Overlapping suffixes error. A bare region after contiguous -L regions may auto-receive -E.

In Wave-only and Multi-wave modes, a WAV sustain loop (smpl) is applied as -L (Start) and -E (End). Other embedded markers (with comments) are still read, but markers at the same timing as sustain Start/End are discarded and logged.

15. Troubleshooting

SymptomWhat to check
EXPORT is disabled The reason is in the log under === Export Preflight ===. ① Is a waveform (valid part) loaded? ② Is WAAPI connected? ③ Is a destination selected in Wwise (or pinned via Keep Target)? ④ Does the export path exist, under the connected project’s Originals?
Cannot connect to WAAPI / timeout Is Wwise Authoring running? Is Enable Wwise Authoring API checked in Project → User Preferences... (restart Wwise after changing it)? Is the HTTP port still the default 8090?
Dropping the XML reports “MTempoTrackEvent (Tempo Track) was not found” An XML exported from something other than the marker track (e.g. the tempo or signature track only) lacks the required data. Select the marker track and redo File → Export → Selected Tracks.
The WAV should contain markers, but none appear after loading In the Audio Mixdown marker option, verify that the intended marker track is the embed target. If another track is selected there, the WAV contains no markers even though you thought they were embedded.
Bar lines do not match the audio / “cannot read iXML TimeReference” warning The WAV lacks its timeline start position. Turn on Insert iXML chunk in the Audio Mixdown dialog, or place the piece at the very start of the project and export from the top.
Dropped several WAVs but multi-wave mode did not start If any file has a matching .xml next to it, pair processing (XML mode / Wave-only) applies instead. Also, sample rate, channel count, and bit depth must match across all files (details in the log).
File-name error at load The file name (without extension) becomes the Wwise object name, so names starting with a digit (e.g. 01_Battle) or Windows reserved names (CON, etc.) are rejected. Rename and reload.
“Regions overlap” error The -L / -E / -R ranges (including the automatic -A) overlap. Fix the cycle-marker ranges in the DAW so they do not overlap.
Markers loaded, but nothing loops Check the marker names. Only -L / -E / -R / -A, names containing Loop, or the “exactly two markers” special case define ranges (4-3).
