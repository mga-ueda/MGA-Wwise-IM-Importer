MGA Wwise IM Importer マニュアル

Interactive Music を、手作業の積み上げから「聴いて決めて渡す」流れへ。

1. このアプリでできること

DAW で設計した音楽の構造を、そのまま Wwise の Interactive Music へ運ぶためのツールです。

Wwise の Interactive Music は、コンテナ・トランジション・Cue・フェードなど組み立てる要素が多く、一つずつ手で実装すると時間がかかります。本アプリなら、波形上で遷移やレイヤーを聴きながら内容を決め、EXPORT 一発で Wwise へ揃えられます。手作業での実装より大幅に時短できます。

Nuendo／Cubase を使っていなくても大丈夫です。 Logic などマーカーを付けられる DAW で書き出した WAV（埋め込みマーカー）でも十分な手間軽減になります。さらに本アプリ自体にマーカーの付与やループ用マーカーのペア移動機能があり、波形エディタすら必須ではありません。レイヤーミュージックでは、何レイヤーあっても、ループポイントの処理は 1 レイヤーに対して作業するだけで、自動的に他のレイヤーへ反映されます。

Nuendo／Cubase があると非常に強力です。 マーカートラックをエクスポートした XML があれば、テンポ・小節・拍子情報を最大限に活かせます。マーカーやサイクルも波形上に「塗る」ように打つことができ、Entry／Exit／ループ設計を視覚的に進められます。

横方向と縦方向の推移を、混在したまま扱えます。 インタラクティブミュージックの推移には、曲から曲へ切り替えるクロスフェードタイプ（横方向）と、レイヤーを重ねるタイプ（縦方向）があります。さらに縦方向には、再生位置を保ったままクロスフェードで曲を差し替えるレイヤー切替タイプと、鳴っている曲にパートを重ねていくアッドレイヤータイプの 2 種類があります。これらのアセットが 1 つのプロジェクトに混じっていても、分け隔てなく同時に推移をプレビューでき、そのまままとめて Wwise へ実装できます。

Wwise に実装したデータをマスター波形として扱う想定です。ワンショット部とループ部をあらかじめ別ファイルにセパレートせず、1 本のマスター上で構造を非破壊に組み立てます。EXPORT では、Wave 単体／複数波形は元 WAV を Originals へコピーし、区間は MusicClip のトリムで合わせます。XML 付きの長尺マスターは曲（-R で区切られた連続区間）ごとに波形を切り出します。ゲインやフェードはソースへ焼き込みません。

実装は WAAPI ＋ 独自処理の組み合わせです。 Wwise の遠隔操作（WAAPI）に加えて、MusicClip トリム・ラウドネス計測・フェードのプロパティ変換などをアプリ側の独自処理で補っているため、WAAPI を呼ぶだけの自動実装ツールでは実現できない実装まで踏み込めます。具体的には次のようなことができます。

  • 曲から曲への切り替えを、抜けタイミングやフェードの入り／抜け、ループ後のワンショット有無などを変えながら、実際に聴いてプレビューできます
  • 複数の曲をグループにまとめて縦に重ね、上乗せ再生や、レイヤー同士をクロスフェードで差し替える切替も確認できます
  • グループの音量バランスを維持したまま実装できます（Loudness Normalization で崩れがちなレイヤー間バランスを Make-Up Gain で自動補正。利用時に推奨）
  • 設定を忘れがちなストリーミング設定（Prefetch Length／Look-ahead Time）も UI から指定して書き出せます
  • 聴いて決めた内容は、WAAPI 経由で Wwise 上に Music 構造として自動生成されます
  • 複数波形の同時ドロップやマーカートラック XML の利用により、何曲でもまとめて実装できます

2. はじめての方へ：全体の流れと用語

使い方は、大きく次の 4 ステップだけです。

  1. 素材を用意する …… 曲の WAV（必要なら XML やマーカーも）。→ 4 章
  2. アプリへドロップする …… ファイルの組み合わせでモードは自動判定されます。切り替え操作は不要です。→ 5 章
  3. 聴きながら調整する …… ループ位置・曲間の遷移・フェード・縦レイヤーを波形上で確認します。
  4. EXPORT を押す …… 元 WAV のコピーと Wwise 上の構造作成が自動で行われます。→ 6 章

本マニュアルには Wwise の用語がいくつか登場します。最低限、次だけ押さえれば読み進められます。

用語ざっくり言うと
Interactive Musicゲームの状況に合わせて曲を切り替えたり重ねたりする、Wwise の音楽再生の仕組み。
Music SegmentWwise 上の音楽の最小単位。「1 区間の波形＋開始点（Entry Cue）＋終了点（Exit Cue）」のセット。
Music Playlist ContainerMusic Segment を並べて「イントロ → ループ」のような再生順を持たせる入れ物。本マニュアルでは「Playlist」と略します。おおむね「1 曲（またはループする 1 状態）」に相当します。
Music Switch Container複数の Playlist を State（ゲームの状態）で切り替える親。Playlist が 2 つ以上あると自動で作られます。
Entry Cue／Exit CueMusic Segment の「本編の開始点／終了点」。この外側（アウフタクトや余韻）は、次の曲と重ねて鳴らせます。
マーカー／サイクルマーカー波形上の目印。マーカーは 1 点、サイクルマーカーは範囲（開始と終了）を持ちます。本アプリはこの目印から「どこがループか」などを読み取ります。
WAAPIWwise Authoring API。本アプリが起動中の Wwise を遠隔操作してオブジェクトを作るための通信窓口です。
Originals フォルダWwise プロジェクトフォルダ内にある、ソース WAV の置き場。本アプリの書き出し先はこの配下を指定します。

3. クイックスタート（まずはこれだけ）

特別な準備なしで、手元の WAV 1 本を Wwise に入れてみましょう。DAW も波形エディタも使いません。10 分程度で「ドロップ → 聴く → EXPORT」の流れが体験できます。

  1. Wwise でプロジェクトを開き、WAAPI を有効にする
    メニュー Project → User Preferences... で Enable Wwise Authoring API にチェックを入れ、Wwise を再起動します（最初の 1 回だけ。詳細は 6 章）。
  2. Wwise の Project Explorer で作成先を選ぶ
    Interactive Music Hierarchy の Default Work Unit など、生成物を置きたいオブジェクトをクリックして選択状態にします。
  3. 本アプリを起動する
    画面下の WAAPI ステータスバーに Wwise のバージョンとプロジェクト名、選択中の作成先が表示されれば接続できています。
  4. 書き出しパスを設定する
    プロジェクトバーの書き出しパスに、Wwise プロジェクトの Originals フォルダ配下（例: Originals\Music。無ければエクスプローラーで作成）を指定します。
  5. WAV を 1 本ドラッグ＆ドロップする
    ログに === Wave 単体モード === と表示され、波形が出ます。Space で再生できます。
  6. （ループさせたい場合）マーカーを 2 本打つ
    波形をクリックしてループ開始位置へシークし、Insert でマーカーを追加。ループ終了位置でも同様に追加します。マーカーがちょうど 2 本なら、その間が自動でループ区間になります（先頭〜1 本目はイントロ、2 本目〜末尾は余韻として扱われます）。マーカーは ▼ のドラッグで微調整できます。
  7. 聴いて確認する
    Space で再生するとループ区間は無限ループします。L でループエンドの少し手前（1 小節前。小節管理がないときは 3 秒前）へジャンプできるので、つなぎ目の確認に便利です。位置が気になったらマーカーを動かして詰めます。
  8. EXPORT（または Ctrl+Shift+E）
    元 WAV が書き出しパスへコピーされ、Wwise 側に Music Playlist Container 一式が自動生成されます。Wwise 側で再生して確認してみてください。

EXPORT ボタンが押せないときは、ログの === Export Preflight === に理由（未接続・作成先未選択・書き出し先が Originals 配下でない、など）が出ています。→ 15 章

この「マーカーを打って区間を決める」が本アプリの基本操作です。慣れてきたら、次章の方式 A／B で DAW からの持ち込みに進むと、テンポ同期や複数曲の一括実装まで広がります。

4. 素材の準備：3 つの方式と選び方

本アプリへ曲を持ち込む方法は 3 つあります。どれを使うかはドロップするファイルの組み合わせで自動判定されるため、アプリ側での切り替え操作はありません。また、どの方式でも読み込み後にアプリ内でマーカーを編集できます（元の WAV には書き戻さない非破壊編集です）。

4-1. どの方式で持ち込むか

方式用意するもの向いているケースできること
A: Nuendo／Cubase の XML Song.wav ＋ 同名の Song.xml（マーカートラックの書き出し） Nuendo／Cubase を使っていて、小節・テンポ管理が必要な実装をしたい（Next Bar 遷移、Custom Cue、1 本のマスターに複数曲など） 小節線・テンポ・拍子の表示、小節単位の操作（Next Bar／Next Beat、メトロノーム、小節ジャンプ）、単発マーカー → Custom Cue、マーカーを「塗る」ように追加（グリッド＝小節・拍に沿って大量のマーカーを一気に付与できる）
B: マーカー入り WAV マーカー（またはサステインループ）を埋め込んだ .wav マーカー入り WAV を書き出せる DAW なら何でも（Nuendo／Cubase のミックスダウンも含む）。イントロ＋ループ程度のシンプルな構成ならこれで十分 埋め込みマーカーからループ／除外などの区間を自動認識。小節・テンポ情報は無し
C: WAV だけ .wav のみ（準備ゼロ） まず試したい／素材 WAV しか無い／完成済みループ曲を大量に流し込みたい アプリ内でマーカーを付与して区間を決める。2 本以上まとめてドロップすれば複数曲を一括実装（複数波形モード）

迷ったときの指針です。

  • 初めて触る → 方式 C（クイックスタートのとおり）。準備なしで全機能の流れを体験できます。
  • Nuendo／Cubase を使っている → まず、ミックスダウンに iXML とマーカーを含めて書き出すことを習慣にしてください（ひと手間ですが、ほぼ必須級に便利です）。「イントロがあってループする」程度のシンプルな構成なら、それだけ（方式 B）で十分実装できます。小節・テンポ管理を必要とする実装（Next Bar／Next Beat での遷移、Custom Cue、1 本のマスターに複数曲を載せる等）をするときだけ、さらにマーカートラックの XML を書き出して方式 A にします。
  • 他の DAW を使っている → 方式 B。マーカー付き WAV を書き出すだけで、ループ設計を持ち込めます。
  • すでにループ加工済みの曲ファイルがたくさんある → 方式 C の複数波形モード。まとめてドロップして一括で Wwise に実装できます。

なお、マーカーが全く無い WAV でも読み込めます。その場合はアプリ内でループマーカーを打つことになり、手順としては波形エディタでループを打ち込む作業と大差なくなりますが、それでも Wwise 実装は自動化され、ループ位置も取りやすい設計です。可能であれば、マーカーを含めた書き出し（方式 B）までは済ませておくことをおすすめします。

WAV の共通条件: 非圧縮 PCM の .wav を使ってください。ファイル名（拡張子を除く）はそのまま Wwise のオブジェクト名になるため、数字始まり（例: 01_Battle.wav）と Windows 予約名（CON、AUX など）は読み込みエラーになります。複数の WAV を同時にドロップする場合は、サンプルレート・チャンネル数・ビット深度が全ファイルで一致している必要があります。

4-2. 方式 A: Nuendo／Cubase の XML を用意する

Nuendo／Cubase のプロジェクトから「マーカートラックの XML」と「WAV」の 2 ファイルを書き出し、同じフォルダに同じベース名で並べます（例: Song.wav と Song.xml）。

XML の書き出しは、小節・テンポ管理を必要とするインタラクティブミュージックの実装を可能にするための追加手順です。単に「イントロがあってループする」だけの曲であれば XML は必須ではなく、マーカーを埋め込んだ WAV（4-3）だけで実装できます。

① DAW 上でマーカーを打つ

マーカートラック上に、曲の構造を次のルールで配置します（名前の末尾で判定します。大文字小文字は区別しません）。

置くもの名前の末尾意味
サイクルマーカー（範囲）-Lループ区間。プレビューで無限ループし、Wwise ではループする Music Segment になります。
サイクルマーカー（範囲）-EExit Cue 以降（ループ後の余韻・リリース部）。ループ部と同じ Music Segment に束ねられ、遷移時に次の曲と重なって鳴ります。
-L の直後に -E を置き忘れても、自動で付与されます。
サイクルマーカー（範囲）-R除外（Remove）。この範囲は書き出さず、Wwise にも登録しません。1 本のマスター上に複数曲を置くとき、曲間の区切りとして使います。
単発マーカー（1 点）（任意の名前）Wwise の Custom Cue になります（名前がそのまま Cue 名）。ゲーム側同期用の目印などに。
  • -L／-E／-R の各範囲は重ねないでください（重なりは読み込みエラーになります）。
  • サイクルマーカーの In／Out、テンポが変わる小節頭、拍子の変更位置では波形が自動で分割されます。-R で区切られた連続区間が 1 つの書き出しファイル＝1 つの Music Playlist になるため、1 本のマスター WAV に複数曲を並べてまとめて実装できます。
  • 曲の頭が小節の途中から始まる場合（アウフタクト）は自動検出され、接尾辞 -A の区間として Entry Cue 前に配置されます。手動で -A を打つ必要は基本的にありません。

② マーカートラックを XML で書き出す

  1. トラックリストでマーカートラックを選択します。選択するのはマーカートラックです——テンポトラックや拍子トラックを書き出しても情報が不足します。
  2. そのマーカートラックの時間基準（タイムベース）をミュージカル（音符）にします。リニア（時計）のままだと、XML にテンポ・拍子が入らず読み込みエラーになります。
  3. メニューの ファイル → 書き出し → 選択トラック（Export → Selected Tracks）を実行し、.xml で保存します。
  4. ファイル名は WAV と同じベース名にします（Song.wav に対して Song.xml）。

マーカートラックをミュージカル時間基準にして書き出した XML には、テンポ・拍子も含まれます。読み込み時に「MTempoTrackEvent (Tempo Track) が見つかりません」と出る場合は、次を確認してください。

  • マーカートラックを選択して書き出したか（テンポ／拍子トラックだけの書き出しでは不足します）
  • マーカートラックがミュージカル（音符）になっているか（リニア／時計だとテンポが入らない）

ミュージカルにする手順（Nuendo／Cubase）

  1. マーカートラックを選択する
  2. インスペクター（左のトラック詳細）の タイムベースをミュージカルとリニアの間で切り替え（音符／時計のボタン）を押し、音符にする

ボタンが見えないとき（マーカートラックでは最初から隠されていることがあります）:

  1. マーカートラックのトラックリストを右クリックする
  2. トラックコントロール設定（Track Controls Settings）を開く
  3. 非表示側から Toggle time base（タイムベースの切替）を選んで追加する
  4. OK したあと、トラック上のボタンで音符にする

③ WAV を書き出す

  1. 同じプロジェクトから ファイル → 書き出し → オーディオミックスダウン で .wav を書き出します。
  2. 書き出しオプションで iXML チャンクとマーカーを含める設定を有効にしてください（推奨・ほぼ必須）。iXML により WAV にタイムライン上の開始位置（TimeReference）が記録され、小節線と波形が正確に一致します。
  3. マーカーのオプションでは、意図したマーカートラックが埋め込み対象になっているかを必ず確認してください。別のトラックが対象のままだと「埋め込んだつもりが埋め込めていない」ことが起こり得ます。
  4. XML と同じフォルダに、同じベース名で保存します。

iXML を入れられない場合は、曲をプロジェクト先頭（1 小節目の頭）に配置して先頭から書き出せば問題ありません（TimeReference が無い／0 のときは「波形先頭＝タイムライン先頭」とみなされます）。曲がタイムラインの途中に置いてある場合は iXML が必要です。

④ ドロップする

Song.wav か Song.xml のどちらか一方（または両方）をアプリへドロップすれば、自動で両方読み込まれます。ログに === Nuendo/Cubase XML モード === と出れば成功です。小節・テンポ・拍子・マーカー・サイクルが波形に重なって表示されます。

4-3. 方式 B: マーカー入り WAV を用意する

Logic をはじめ、マーカーを WAV に埋め込んで書き出せる DAW・波形エディタなら何でも使えます。Nuendo／Cubase のオーディオミックスダウン（マーカーを含める設定）もこの方式に使えます——「イントロがあってループする」程度のシンプルな構成なら、XML を作らずこれだけで十分です。読み取られるのは次の 2 種類です。

  • サステインループ（smpl チャンク） …… サンプラー用のループ情報です。あれば最優先で採用され、ループ Start が -L、End が -E として扱われます。ループの Start／End と同じ位置にある通常マーカーは破棄されます（ログに記録されます）。
  • 通常のマーカー（cue ポイント） …… 名前（コメント）で意味を判定します。

通常マーカーの名前ルールは次のとおりです。区間は「そのマーカーから次のマーカー（無ければ波形終端）まで」です。

マーカー名意味
-Lここからループ区間。
-Eここから Exit Cue 以降（余韻）。
-Rここから除外（書き出さない）。
-Aここから Entry Cue 前（アウフタクト）。
Loop を含む名前-L と同等。2 個で挟むとその間がループ区間になります（奇数個の余り 1 個は単独 -L 扱い）。
上記以外の名前区間を開始しません（表示・編集用の目印）。ただし「次のマーカー」として、直前の特殊区間の終端にはなります。
  • 特例: マーカーがちょうど 2 本で特殊な名前が無い場合、その間が自動でループ区間になります。「ループの入りと出にただ目印を打っただけ」の WAV がそのまま使えます。
  • 特殊名のマーカーが 1 つも無い場合は、曲全体が 1 区間（頭が Entry Cue、末尾が Exit Cue）として扱われます。ワンショット曲はマーカー無しで OK です。
  • 小節線・テンポは表示されません（テンポ同期の機能を使いたい場合は方式 A へ）。
  • リージョン（cue＋ltxt）だけが入った WAV は現在未対応です。ポイントマーカーかサステインループをお使いください。
  • 埋め込みマーカーはプレビューと区間分割にのみ使われ、Wwise の Custom Cue には出力されません（Custom Cue が必要なら方式 A の単発マーカーを使います）。

4-4. 方式 C: WAV だけで始める（アプリ内でマーカーを打つ）

準備は不要です。.wav をそのままドロップし、アプリ内でマーカーを打って区間を決めます。操作は波形下のマーカーレーンで行います（元の WAV には一切書き込みません）。

  • Insert …… シーク位置にマーカーを追加
  • ▼ をドラッグ …… マーカーを移動（Alt＋ドラッグで 1 つ前のマーカーも同量移動——ループ範囲の長さを保ったままのスライドに便利です）
  • ▼ やコメントをダブルクリック …… 名前（コメント）を編集。-L／-E／-R／-A の意味は方式 B と同じです
  • Delete …… 選択したマーカーを削除、Ctrl+Z／Y …… Undo／Redo

複数曲をまとめて実装したい場合は、2 本以上の WAV を同時にドロップしてください（複数波形モード）。仮想タイムライン上に連結表示され、1 ファイル＝1 Music Playlist として一括で Wwise に登録できます。各ファイルの埋め込みマーカー（方式 B のルール）もそのまま有効です。

5. 読み込みモードの判定ルール

ドロップするファイルの組み合わせでモードが決まります。ログ先頭の見出しで現在のモードを確認できます。

ドロップしたものモード（ログの見出し）
.wav 1 本（同名 .xml なし）=== Wave 単体モード ===
.wav 2 本以上（いずれも同名 .xml なし）=== 複数波形モード（XML なし） ===
同名の .wav ＋ .xml（どちらか一方のドロップでも可）=== Nuendo/Cubase XML モード ===
.xml のみ（同名 .wav が見つからない）エラー（波形表示には .wav が必須）

5-1. Wave 単体（XML なし・WAV 1 本）

手順

  1. 同名の .xml が無い .wav を 1 本、アプリへドロップする
  2. ログに === Wave 単体モード === と出ることを確認する
  3. 埋め込みマーカーがあれば読み込み、なければ全体を 1 パートとして扱う
  4. 必要ならアプリ上でマーカーを編集する（WAV には書き戻さない）

ポイント

  • 小節線・テンポ・拍子は表示されません（Exit Source At の Next Bar／Next Beat も使えません）
  • More Options の Marker Comment／Marker Grid は無効です（Wave 単体は 4-4 のマーカー編集操作を使います）
  • 埋め込みマーカーの読み込みに加え、アプリ上での付与・移動・ペア移動が可能です（WAV には書き戻しません）。波形エディタでの事前分割が不要なケースが多いです
  • Playlist を Shift+クリック／ドラッグでグループ化（縦レイヤー）すると、マーカーは基準 Playlist から全メンバーへ投影され（同期先には半透明で表示）、追加・削除・移動（ペア移動を含む）が自動でシンクロします。1 か所の編集で全レイヤーのマーカーが揃うのが大きな魅力です
  • 埋め込み／編集したマーカーはプレビューとリージョン分割に使い、Wwise Custom Cue には出しません
  • WAV にサステインループ（smpl）がある場合、その Start を -L・End を -E として扱います。通常の埋め込みマーカーより優先し、ループ Start／End と同タイミングのマーカーは破棄します（ログに記録）
  • 書き出し名の目安: 基底名_1.wav など（波形ファイル名のダブルクリックで基底名を編集可）

5-2. 複数波形（XML なし・WAV 2 本以上）

手順

  1. 2 本以上の .wav を同時にドロップする（どれにも同名 .xml が無いこと）
  2. ログに === 複数波形モード（XML なし） === と出ることを確認する
  3. 仮想タイムラインへ連結され、1 ファイル＝1 Music Playlist として並ぶ（何曲でもまとめて実装可能）
  4. 必要なら Shift でグループ化（縦レイヤー）する

ポイント

  • Sample Rate／チャンネル数／ビット深度などが一致している必要があります（不一致だと読み込み中止）
  • ファイルごとの埋め込みマーカー／サステインループ（smpl）は Wave 単体と同じ規則で処理します（サステインの Start／End → -L／-E 優先。同タイミングのマーカーは破棄）
  • グループ化した Playlist（縦レイヤー）では、マーカーが基準 Playlist から全メンバーへ投影され（同期先には半透明で表示）、追加・削除・移動（ペア移動を含む）が自動でシンクロします。全レイヤーのループ位置を 1 回の操作で揃えられるのが大きな魅力です
  • Wwise 側の親名は固定で Multi_Wave（編集不可）。Playlist 名はドロップ時のファイル名を維持します
  • 書き出しでは可能な範囲で元 WAV を共用し、ファイル名をむやみに改変しません
  • 1 本でも同名 XML があると、このモードには入らず後述のペア処理になります

5-3. WAV ＋ 同名 XML（マーカートラックのエクスポート）

手順（XML と WAV の作り方は 4-2 を参照）

  1. Nuendo／Cubase でマーカートラックを XML エクスポートし、同じフォルダに同じベース名の .wav と並べる（例: Song.wav と Song.xml）
  2. どちらか一方、または両方をドロップする
  3. ログに === Nuendo/Cubase XML モード === と出ることを確認する
  4. 小節・テンポ・拍子・マーカー／サイクルが波形に重なる

ポイント

  • テンポ・小節・拍子を最大限に利用できます。マーカー／サイクルは波形上に塗り重ねるように表示され、構造設計がしやすくなります
  • 1 本のマスター上に複数パート／複数曲相当の区間を置けば、まとめて Wwise へ実装できます
  • XML 由来の単発マーカーは Wwise Custom Cue にも使われます
  • Shift＋Marker レーン左ドラッグで追加マーカー（Custom Cue 用）。Ctrl＋ドラッグで追加分だけ消去（XML 由来は消しません）
  • Marker Comment／Marker Grid が有効です
  • .xml だけのドロップはエラーです（波形表示には .wav が必須）

読み込み時の注意

  • 複数のペアを一度にドロップした場合、処理は順に行いますが、画面に残るプレビューは最後に成功した 1 件です
  • 手動ドロップではログがクリアされ、その読み込みは「やり直し」扱いです（Keep Last Session の自動復元はしません）
  • RELOAD …… アプリを開いたままソース WAV／XML が更新されたときに、同じファイルをディスクから再読み込みします。グループ／フェード／追加マーカー等のいまの作業内容は可能な範囲で維持します（ログは消しません）。波形の内容が大幅に変わっていると維持しきれず表示や設定がおかしくなることがあるので、そのときは手動ドロップでやり直してください
  • Keep Last Session …… 起動時／プロジェクト復帰時に、保存済みセッション（グループ／フェード等）を可能な範囲で復元します

6. Wwise 側の準備と EXPORT

6-1. WAAPI を有効にする（最初の 1 回だけ）

本アプリは、起動中の Wwise Authoring と WAAPI（HTTP）で通信してオブジェクトを作ります。

  1. Wwise のメニュー Project → User Preferences... を開く
  2. Enable Wwise Authoring API にチェックを入れて OK
  3. Wwise を再起動する

本アプリの接続先は http://127.0.0.1:8090/waapi（同じ PC の Wwise、HTTP ポート 8090）で固定です。User Preferences で HTTP ポートを既定の 8090 から変更している場合は、既定に戻してください。

6-2. 作成先と書き出しパス

  • 作成先 …… Wwise の Project Explorer で、生成物を置きたいオブジェクト（Interactive Music Hierarchy の Work Unit や Virtual Folder など）をクリックして選択します。本アプリは「Wwise 上でいま選択されているオブジェクト」を作成先として使います。毎回選び直すのが煩わしい場合は、WAAPI ステータスバーの Keep Target で固定できます。
  • 書き出しパス …… プロジェクトバーで、元 WAV のコピー先を指定します。接続中の Wwise プロジェクトの Originals フォルダ配下である必要があります（例: <プロジェクト>\Originals\Music\IM-Importer）。Wwise がソース WAV を参照できる場所に置くためです。

6-3. EXPORT の手順

  1. Wwise Authoring を起動し、WAAPI を有効にしておく（6-1）
  2. Project Explorer で作成先オブジェクトを選択する
  3. アプリの書き出しパスに、接続中プロジェクトの Originals 配下を指定する
  4. 5 章のいずれかのパターンで波形を読み込む
  5. 遷移・フェード・グループ化などをプレビューで確認する
  6. EXPORT（または Ctrl+Shift+E）を実行する

EXPORT は次の 4 条件が揃うと有効になります: ①有効パートあり ②WAAPI 接続中 ③作成先選択済み ④書き出し先が存在し Originals 配下。未達の理由はログの === Export Preflight === に出ます。

重要 — 同名ファイルの上書き: 書き出しパスに同名の WAV がある場合、EXPORT は確認なしで上書きしますので、ご注意ください。

先頭 Music Segment の Look-ahead を 50 ms 固定にしている理由: Loudness Normalization・Voice Volume・ゲインなど手段を問わず、元波形が持つ音量より極端に低い音量を Wwise 上で指定した場合、音量が確定するまでに数ミリ秒かかるようで、波形冒頭が一瞬元の音量のまま聴こえる挙動が確認されています。この症状はオーサリングツール上でのみ確認されており、実機では発生しない模様です。安全策として 50 ms を設定しています。Zero latency を利用している場合は 0 にしたいところですが、0 ms だとソーススタベーションエラーが出るため、致し方なく 50 ms にしています。この処置は現状暫定的なものであり、今後変更される可能性があります。

なぜ Keep Layer Balance が必要か: Wwise の Loudness Normalization は音源ごとに一律でターゲットラウドネスへ揃えるため、意図的に控えめにミックスしたレイヤーまで他と同じ音量へ持ち上げられ、グループ内の音量バランスが崩れてしまいます。オンにすると、EXPORT 時にグループ内各パートの Integrated Loudness（LKFS）を計測し、最も大きいパートの Make-Up Gain を 0 dB、それ以外は相対差のぶんだけ下げて設定します。これにより Normalization 後も DAW で決めたレイヤーバランスがそのまま再現されます。補正は Music Track の Make-Up Gain への非破壊設定で、WAV には焼き込みません。

13. EXPORT と Wwise に作られるもの

Wwise 上の Interactive Music 実装をマスターとして扱う想定です。ワンショットとループをあらかじめ別 WAV に分けず、マスター波形上の構造を非破壊で組み立てます。Wave 単体／複数波形は元 WAV のコピーと MusicClip トリム、XML 付きは曲ごとの切り出しです。フェード・レイヤーバランス・Cue は Wwise プロパティへ設定します（ソースへ焼き込みません）。

  • パートまたはグループ 1 つ → Music Playlist Container 1 つ
  • Playlist が 2 つ以上 → Music Switch Container ＋ 同名 State Group
  • グループ（2 パート以上）→ 1 Music Segment 内の複数 Music Track ＋ グループ State Group（A／B／C…）
  • Any → Any（Exit Source At = Immediate）と各 Playlist 向け Any → Object（Fade／Exit Source At／Play post-exit）
  • 各 Playlist Container 内の既定ルール（Any to Any）→ Play -E に応じた Play post-exit
  • リージョン端フェード → MusicClip Fade／Keep Layer Balance → Make-Up Gain
  • Nuendo／Cubase XML モードの単発マーカー → Custom Cue。テンポ・拍子は Music Segment で Override

同名ファイルの上書きに注意: 書き出しパスに同名の WAV がある場合、EXPORT は確認なしで上書きしますので、ご注意ください。

14. 接尾辞と Cue

接尾辞意味
-R除外
-Lループ
-EExit Cue 以降（同一 Music Segment に束ねる）
-Aアウフタクト／Entry Cue 前（同一 Music Segment に束ねる。自動付与あり）

重複配置はエラー。-L 連続の直後に接尾辞が無い場合、-E が自動付与されることがあります。

Wave 単体／複数波形では、WAV のサステインループ（smpl）があればその Start を -L・End を -E として採用します。通常の埋め込みマーカー（コメント付き）も読み取りますが、サステインの Start／End と同タイミングのマーカーは破棄し、その旨をログに出します。

症状確認すること
EXPORT が押せない ログの === Export Preflight === に理由が出ています。①波形（有効パート）を読み込んでいるか ②WAAPI 接続済みか ③Wwise 側で作成先を選択しているか（または Keep Target 済みか） ④書き出しパスが存在し、接続中プロジェクトの Originals 配下か。
WAAPI に接続できない／タイムアウトする Wwise Authoring が起動しているか。Project → User Preferences... で Enable Wwise Authoring API にチェックが入っているか（変更後は Wwise 再起動）。HTTP ポートが既定の 8090 のままか。
XML のドロップで「MTempoTrackEvent (Tempo Track) が見つかりません」 マーカートラック以外（テンポ／拍子トラックのみ等）を書き出したか、マーカートラックがリニア（時計）のままかを確認してください。マーカートラックをミュージカル（音符）にしてから ファイル → 書き出し → 選択トラック をやり直してください。切替手順は 4-2 にあります。
マーカーを埋め込んだはずの WAV なのに、読み込んでもマーカーが出ない ミックスダウンのマーカーオプションで、意図したマーカートラックが埋め込み対象になっているかを確認してください。別トラックが対象のままだと、埋め込んだつもりでも WAV にマーカーは入っていません。
小節線と波形がずれる／「iXML の TimeReference が取れません」と出る WAV にタイムライン開始位置が記録されていません。ミックスダウン時に iXML チャンクを挿入 をオンにするか、曲をプロジェクト先頭に置いて先頭から書き出してください。
複数の WAV をドロップしたのに複数波形モードにならない どれか 1 本に同名の .xml が隣にあると、ペア処理（XML モード／Wave 単体）に切り替わります。また、サンプルレート・チャンネル数・ビット深度が全ファイルで一致していないと読み込みを中止します（ログに詳細）。
ファイル名のエラーで読み込めない ファイル名（拡張子を除く）は Wwise オブジェクト名になるため、数字始まり（例: 01_Battle）と Windows 予約名（CON など）は使えません。リネームしてから読み込んでください。
「リージョンが重なっています」のエラー -L／-E／-R（自動の -A 含む）の範囲が重なっています。DAW 側でサイクルマーカーの範囲が重ならないよう修正してください。
マーカーは読めたのにループしない マーカー名を確認してください。区間として解釈されるのは -L／-E／-R／-A、名前に Loop を含むもの、または「マーカーちょうど 2 本」の特例のみです（4-3）。

17. 対応範囲と位置づけ

  • 本アプリは、Wwise の Interactive Music で出来ることをすべてカバーするものではありません。よく行われる手順に絞って機能を実装しています。たとえばフェードタイムはプリセットからの選択式ですし、推移タイミングの指定にも、Wwise にはあって本アプリには無い項目があります。
  • アプリ内でのプレビューは、実装結果をざっくり事前確認するまでの位置づけです。アプリ独自の再生エンジンによる近似のため、Wwise 実機の挙動と完全に一致するとは限りません。最終確認と追い込みは、EXPORT 後に必ず Wwise 上で行ってください。
  • 本アプリは基本的にビュワー＆インポーターであり、エディタではありません（マーカーの編集など、多少のエディットはできます）。細かい作り込みは Wwise 上で行う前提です。
  • ソース WAV には一切書き込みません（非破壊）。一方で EXPORT は Wwise プロジェクトにオブジェクトを作成・変更するため、実行前に Wwise プロジェクトのバックアップやバージョン管理をおすすめします。
  • EXPORT は、書き出しパスにある同名の WAV を予告なく上書きしますので、ご注意ください。
